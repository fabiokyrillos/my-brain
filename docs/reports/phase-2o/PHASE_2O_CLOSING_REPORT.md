## 3. The five things that did not get built, and why that is the answer

`not-built-by-rule` is the class that asserts an external permission, and all
five of this phase's are the same permission.

**`2O-METRICS-001` … `-005` close `not-built-by-rule` under `OD-2O-8` A and
ADR-118 Decision 3.** The condition had two conjuncts and both failed:

- **No producer.** `src/features/activation/` exports a fact vocabulary, a
  progress derivation and one read. `grep` for `recordProductEvent` across it
  and `src/features/onboarding/` returns **zero**.
- **No consumer.** `scripts/` holds funnel readers for Phases 2F, 2J, 2K and 2M
  and **none for 2O**.

**Nothing was invented to spend the allocation.** No event, no artificial
producer, no documentary code called a consumer — the last of which slice 2O.6
caught slice 2O.5 doing once, and the lesson was applied rather than re-learned.

The five questions the phase *wanted* answered are written down in
`PHASE_2O_SLICE_8_M1_VERDICT.md` §2, before any event name, so a later phase
inherits the thinking rather than the omission.

## 5. The one requirement that changed, and the one that moved

### `2O-NOTIFY-005` — corrected rather than built

It asked for an **important-reminder override** to be stated where consent is
given. There is none: `decideDelivery` refuses inside quiet hours with no
exemption for type, priority or urgency.

**ADR-120 corrects the requirement.** Quiet hours always wins, the daily cap
continues to apply, no type or urgency passes either, and the surface says so
explicitly — which it already did, in both locales. **The identifier is
unchanged, nothing was renumbered, and the superseded sentence is quoted beneath
the new one.** 116 declared before the correction and 116 after.

**The correct response to a requirement describing a capability the product does
not have is to correct the requirement, not to build the capability to match the
sentence.**

### `2O-PREF-002` — under-stated for three slices

Classified `partial` by slice 2O.3 because the consent record had no surface.
**Slice 2O.5 built it** — `ConsentSection`, mounted on Ajustes at
`settings/page.tsx:180` — and said so, but its classification table covered a
different family, so **nothing re-classified the requirement**.

The closeout adjudicates it to **`built`**, explicitly, after verifying the mount
in the tree rather than reading the claim.

**This repository's standing risk is over-stating shipped UX — Phase 2I's audit
did it three times. Here the matrix would have under-stated it.** Both directions
are wrong, and only a closeout that re-derives from source catches the second.

## 6. What the closeout's own machinery got wrong

`2O-CLOSE-002` requires the matrix to be generated, never typed. The generator
found **four defects, all mine**. Three refused. **One answered.**

The one that answered is the one worth carrying: the adjudications were first
written in a four-column table — `Requirement | Was | Now | Why` — and the
generator reads a class **positionally, from the second cell**, which in that
shape is **`Was`**. It read `2O-PREF-002` as the class the adjudication exists to
overturn and **wrote a matrix saying so**. No refusal. The counts were 105/3
before and 106/2 after, and nothing but reading the rendered row distinguished
them.

**The fix was not a smarter parser but one row shape per record.** A positional
rule is only sound while the positions are the same everywhere.

Two of my own edit scripts made the mirror error the same hour, matching `---`
against a table separator instead of a section break — which left a fragment of
the old table behind that the generator then read as a second classification.

**A gate that refuses is telling you something. A gate that answers is only
telling you something if you check the answer against the thing itself.**
