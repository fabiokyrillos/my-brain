## 3. The migration was not spent, and the measurement is why

Gate **G-2I.2** measured **before** any search code existed, as instructed.

| Shape | scale 1 | scale 2 | Budget 300 ms |
| --- | ---: | ---: | --- |
| Sequential — one `UNION` round trip | 338–354 ms | 669 ms | **FAIL** |
| **Parallel — slowest single domain** | **121–191 ms** | **244 ms** | **PASS** |

**The parallel shape was not chosen to fit the budget — it was already required.**
`2I-SEARCH-006` (per-domain bounds) and `2I-SEARCH-007` (a *named* per-domain
failure) are both meaningless unless each domain is queried independently.
Having required that, the wall clock is the slowest domain.

**Revisit threshold, recorded so it is re-measurable rather than re-arguable:**
re-run the benchmark when any single owner passes **~10 000 entries** or
**~1 000 attachments carrying `extracted_text`**. Growth is linear, and the two
dominant columns are `entries.original_content` and
`attachments.extracted_text`.

`1 allocated · 0 spent` — **the preferred close, not a shortfall** (ADR-093).

## 4. What the audit got wrong, three times

The phase's own `PHASE_2I_CURRENT_EXPERIENCE_AUDIT.md` over-stated remaining
navigation work in three places, each caught by reading the source:

1. **`chat: "Conversar"` was already shipped** — the earlier planning study
   listed it as pending.
2. **`Mais` already renders grouped destinations** with visible labels and
   `role="group"` on both breakpoints. The audit called it *"an undifferentiated
   list of twelve"*. `2I-SHELL-003` was reclassified `built` → **`baseline`**.
3. **Library's membership already existed as data** (`group: "context"`), so
   Library is a rendering rather than an information architecture.

**This is why the matrix carries `baseline` as a distinct class.** A phase that
reported assertions of existing behaviour identically to things it built would
overstate itself — and this phase would have overstated itself three times.

The rule the PRD imposed in response is now proven necessary: **a requirement
claiming a rename or a rebuild must cite the exact constant or component it
changes.**

## 6. Security posture — what this phase added

**Nothing.** No write path, no model call, no RLS policy, no grant, no secret,
no external service, no migration, no privileged boundary.

Two threats were real and both are closed structurally:

**T-2I-01 — search as an enumeration oracle.** Ownership is the authenticated
client plus forced RLS, applied **in the query**. Proved in pgTAP **with two
accounts** (`phase_2i_search_ownership.sql`, 18 assertions): two owners, rows
matching the *same* needle, each asserted to see only their own, **in both
directions** — because `user_id = auth.uid()` and `user_id = '<A>'` are
indistinguishable from one side. The guard's first assertion is not *"the query
is owner-scoped"* but **"no file in this feature can construct a service-role
client"**, because that is the failure RLS cannot save you from.

**T-2I-02 — the palette as a second write path.** Closed three ways: the
directory constructs no client; **an action has no invocable field** (the test
walks every action and asserts no property is a function); and the query
**cannot invent an action** — for `'; drop table tasks; --`, `<script>` and
`../../etc/passwd`, every filtered result is asserted to be a member of the
pre-built list. *User text selects; it never constructs.*

## 7. OD-1 and OD-2 as implemented

**OD-1.** `highly_sensitive` is excluded by a predicate **inside** each query,
so an excluded row is never retrieved. The default state leaks neither existence
nor count — the guard forbids `hiddenCount`, `excludedCount`, `sensitiveCount`,
`hasHidden`, `omitted`, and **the empty-state copy deliberately does not suggest
enabling sensitive search**, because that suggestion is an existence oracle with
a helpful tone. The scope is visibly active while results show, and is not
persisted.

**OD-2.** `attachments.extracted_text` is searched. Snippets are 160 characters,
centred on the match, whitespace-flattened so a row cannot be inflated, rendered
as text, never sent to a model, and subject to OD-1. No durable duplicate of the
column.

## 10. Fifteen defects, and where they were

**Thirteen of fifteen were in probes, fixtures, guards or tooling** — not in the
product.

The most consequential never became a failure at all: the search benchmark's
first design relied on the Management API not committing. That is a guess about
someone else's transaction handling, and being wrong would have left thousands
of fixture rows in production. It became a `DO` block whose only exit is a
`raise`, verified by reading the table back on every run.

The most instructive cluster: **three guards failed on correct product code
because they scanned raw text including comments** — a header saying *"no `pt ?`
ternary is added"* was read as the violation, and a stylesheet saying *"there is
no `prefers-color-scheme` block here"* was read as one too. Same root cause,
three symptoms.

Two were mine in the generator itself, and both were caught by the generator
refusing: it rejected `partial` as an unknown class (the contract permits it —
the omission was mine) and it could not be imported by its own test until the
repo-root computation matched Phase 2H's pattern. **A generator no test can
import is a generator nothing proves.**

Two guards caught genuine new-code issues: the reachability inventory flagged
both new routes the moment they appeared, and lint caught an active-index reset
in an effect that would have announced a stale highlight.
