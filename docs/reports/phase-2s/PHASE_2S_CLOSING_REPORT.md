# Phase 2S — Closing report

**Responder ao Brain: o que o produto diz, e o que você pode dizer de volta.**

**THIS REPORT DOES NOT CLOSE THE PHASE.** `2S-CLOSE-010` makes closure an owner
decision recorded as an ADR **after a closing device checkpoint**, and neither
has happened. A green pipeline is not that, a generated matrix is not that, and
this document is not that. It is the material the owner would need in order to
decide, and nothing more.

## 1. What the phase set out to end, and what actually moved

The subject was measured on 2026-08-24: **three tasks nobody had touched in
twenty-five days had produced fifty-four notices in eighteen, and not one had
been read.** The diagnosis was that this is the rational response to a message
that cannot be answered.

`2S-CLOSE-012` requires the same query at closeout. Run on 2026-08-27:

| | 2026-08-24 | 2026-08-27 | moved? |
|---|---|---|---|
| notifications | 57 — 54 `task_stale`, 3 `task_overdue` | 57 — 54, 3 | no |
| **rate** | **exactly 3 per day**, 08-17 → 08-24, unbroken | **zero per day**, 08-25 · 08-26 · 08-27 | **YES** |
| read | 0 of 57 | 0 of 57 | no |
| dismissed | 0, and unreachable | 0, reachable and never reached | **the reachability did** |
| suppressions | — | 0 | never used |
| delivered by push | 0 | 0 | no |

### The half that moved, and the four attempts to break the conclusion

**The daily repetition stopped on the day slice 2S.1's migration landed.** That
claim was attacked before it was written:

- the heartbeat **did not stop** — 48 runs in 48 hours for that account, every
  one `completed`;
- the three subject tasks **did not change** — still `inbox`, no due date,
  `updated_at` still 2026-07-30;
- **no suppression exists** on that account, so the silence is not an owner
  saying *not this*;
- the mechanism was read from the **deployed function**, not the migration file.
  `pg_get_functiondef(run_user_heartbeat)` carries the ladder — `0 → send`,
  `1 → +1 day`, `2 → +3 days`, `3 → +7 days`, **`else → false`**. With 54 prior
  notices about subjects that have not moved, the terminal branch is `false`.

That is `OD-2S-4` **A** — escalate, then go silent — working on the exact rows
the phase was chosen for.

### The half that did NOT move, stated plainly

**`read`, `dismissed` and `notification_suppressions` are all zero.** Nobody has
answered a notice in production. Everything this phase built for *answering* is
proved by unit tests, by pgTAP against the deployed schema, and by one hosted
lane on a **disposable** account — and by none of the product's real use.

The owner approved the measurement above **as evidence that the cadence stopped
and explicitly not as evidence of real user response.** This report carries that
distinction rather than blurring it, and §6 keeps the gap open as its own item.

## 4. `2S-TRUST` — the honesty family, disposed

**No new write authority.** The five handlers the one shared bundle dispatches to
were each looked for at slice 2S.0's merge commit `39bb4b8`:
`markNotification`, `applyWorkItemAction`, `applyTaskDetailCommand` and
`undoWorkOperation` were **present**; `suppressNotificationSubject` was
**absent**, and it is the phase's one new authority, riding its one allocated
migration. Refusal 20 reads that bundle from the tree, so the claim can fail.

**The heartbeat is the only producer of a notice, and the enumeration is wider
than the requirement's sentence.** Three writers exist —
`run_user_heartbeat` (INSERT), `prune_notifications` (DELETE, Phase 2H) and
`markNotification` (UPDATE of `status`/`read_at`) — and **this phase added none
of them.** Recorded as a finding rather than reported as the one that fits.

**No notification content reaches any new store.** `notification_suppressions`
holds a subject reference, a scope, an expiry, an actor and the owner's own
`reason`; there is no column a title or body could occupy.

**Zero AI calls and zero credential spend**, and it is a live refusal rather than
a vacuous one: the BYOK credential is `active`, so a call was possible and none
was made.

**Push is not resumed, not repaired, and not claimed.** `notification_deliveries`
holds zero rows and the HTTP 403 is untouched and carried to `OD-2S-6`. Refusal
18 enforces this by forbidding the **claim** rather than the word, so the
sentence this report most needs — that push still does not work — stays sayable.
